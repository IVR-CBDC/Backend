# SPA на настоящем API — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Перевести SPA с мок-контракта на реальный BFF: экраны входа и регистрации, ISO-коды стран, живые котировки комиссии, подача документов с оптимистической блокировкой, трекинг и перезапрос по событиям WebSocket.

**Architecture:** SPA не знает про токены — сессия живёт в `HttpOnly`-cookie BFF, поэтому весь запрос — это `credentials: "same-origin"` и ветвление по `code` из конверта ошибок. События WebSocket не несут данных: каждое из них и каждый `connection.ack` (включая переподключения) — команда «перезапроси текущий экран», потому что у Redis pub/sub нет истории и дыру после разрыва обнаружить нельзя. `version` сделки прокидывается насквозь: без неё core отвечает `409 VERSION_CONFLICT`.

**Tech Stack:** React 18, TypeScript 5.5, Vite 5, react-router 6, vitest + @testing-library/react + jsdom, nginx (образ).

**Spec:** `docs/superpowers/specs/2026-09-15-cbdc-hub-integration-design.md` (§7 Frontend SPA, §3.1 аутентификация, §9 строка «Component (vitest + Testing Library)»).
**Контракт BFF↔SPA:** раздел «Контракт для SPA» в `README.md` Frontend-репозитория — словарь кодов ошибок, формы кадров WS, правило перезапроса. Это источник правды, а не догадки по коду BFF.

**Два репозитория.** Основная работа — `/home/legors/Documents/alfa-cbdc-hub`, ветка `main`. Task 5 дополнительно меняет `/home/legors/Documents/IVR` (Backend) в ветке `feat/frontend-service` — отдельный коммит.

## Global Constraints

- Все запросы к BFF идут с `credentials: "same-origin"`. Токенов в коде SPA нет и быть не может: cookie `HttpOnly`.
- Ошибки разбираются по `code`, не по тексту. `401` (`UNAUTHORIZED`, `TOKEN_EXPIRED`, `INVALID_TOKEN`) → на экран входа; `409 VERSION_CONFLICT` → «сделка изменилась, обновите»; `503 UPSTREAM_UNAVAILABLE` → «сервис временно недоступен», с возможностью повторить; остальное — текст из `error`.
- Страны в API — ISO 3166-1 alpha-2 (`CN`, `TR`, `IN`, `AE`, `KZ`, `BY`), валюты — ISO 4217 (`RUB`, `USD`, `CNY`, `AED`, `INR`, `TRY`, `KZT`, `BYN`). Пользователю показываются русские названия, в запрос уходит код.
- `version` сделки прокидывается в `POST .../scenario` и `POST .../documents/:id/submit` без изменений.
- На каждый `connection.ack` и на каждый `DealEvent` — перезапрос текущего экрана целиком. Патчить состояние из полей события запрещено.
- Существующая вёрстка и CSS сохраняются: это работа Мари. Меняется слой данных, а не оформление; новые экраны (вход, регистрация) верстаются в том же стиле.
- Тесты компонентов гоняются без BFF: `fetch` подменяется.
- Никаких `git push` и операций с кластером. Контейнеры `registry`, `legors-db`, `tealdeer-db` не трогать.
- Сообщение коммита заканчивается строкой `Co-Authored-By: Claude <модель> <noreply@anthropic.com>` — модель та, что реально пишет коммит.
